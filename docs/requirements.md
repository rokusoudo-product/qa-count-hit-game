## 1. プロダクトビジョン

複数人がリアルタイムでQRコードを使ってグループを形成し、質問への回答人数を予測し合う、
パーティー向けAndroidアプリ。六創堂の技術力アピールとしてGoogle Playで公開する。

## 3. 機能要件

### 3.1 ルーム管理
- ホストがルームを作成できる
- ルーム作成時にQRコードが生成される
- QRコードをスキャンしてルームに参加できる
- ルームには最大20人まで参加できる（初期設定）
- ホストがゲームの開始・終了を制御できる

### 3.2 質問・回答フェーズ
- ホストが事前設定した質問が全参加者に表示される
- 質問は二択形式（例：「犬派？猫派？」）
- 全員が時間内に回答する（タイムアウト設定あり）
  - 回答時間（answerSeconds、デフォルト30秒）＋猶予3秒が経過すると、未提出者がいてもホスト端末が
    提出済みの回答だけを集計して予測フェーズへ強制的に進める
  - タイムアウトの基準時刻は、Firestoreのルームドキュメントに保存したフェーズ開始時刻
    （`phaseStartedAt`、サーバー時刻）から算出する。途中参加・画面復帰した端末でも基準時刻はズレない
- 回答はリアルタイムでサーバーに送信される

### 3.3 予測フェーズ
- 回答集計後、「〇〇を選んだのは何人か？」という予測フェーズに移行
- 各参加者が人数を入力して予測する
- タイムアウト設定あり
  - 予測時間（predictSeconds、デフォルト20秒）＋猶予3秒が経過すると、未提出者がいてもホスト端末が
    提出済みの予測だけでラウンドを確定させる（未提出者は当該ラウンドのスコア集計から除外される）
  - 基準時刻の算出方法は3.2と同様、`phaseStartedAt` を用いる

### 3.4 採点・結果表示
- 予測値と実際の回答人数の差が小さいほど高得点
- ラウンドごとのスコアと累計スコアを表示
- 最終的なランキングを表示

### 3.5 リアルタイム通信
- Cloud Firestore のリアルタイムリスナー（`addSnapshotListener`）による同期。WebSocket もポーリングも使わない
- 参加者の入退室・回答状況をリアルタイム反映
- クライアント（Android / Web）は Firestore を**直接読み書き**する。Cloud Functions は実装済みだが経由していない（`docs/architecture.md` 参照）

## 4. 非機能要件

| 項目 | 要件 |
|------|------|
| プラットフォーム | Android（minSdk 26 / API Level 26以上）＋ Web ブラウザ（参加・ホストとも可） |
| 同時接続数 | 1ルームあたり最大20人 |
| レスポンス | 回答反映は3秒以内 |
| 可用性 | Firebase（Cloud Firestore + Authentication + Hosting）のマネージドサービスに依拠する |
| セキュリティ | ルームIDは8桁のランダム文字列（`ABCDEFGHJKLMNPQRSTUVWXYZ23456789` の32文字集合。誤読しやすい `I`/`O`/`0`/`1` を除外）。Firestore セキュリティルールでルーム単位に権限を絞る |
| コスト | Firebase（GCP）無料枠での運用を優先 |

> ⚠️ 採点処理をクライアントが実行する構成のため、**同一ルームの参加者によるスコア改ざんはセキュリティルールでは防げない**。無関係な第三者による覗き見・妨害は塞いである。詳細と対処方針は `docs/architecture.md`「セキュリティ」を参照。
